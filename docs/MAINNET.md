# Mainnet readiness

Everything in Receptum runs on testnets today, and testnet stays the default everywhere. The mainnet code paths are implemented behind an explicit opt-in (§2), so going live is: fund a fresh key, then run the deploy script. **Nothing has been deployed to a mainnet yet.**

## 0. Funding and the audit rule

Mainnet deployment and the independent audit are to be funded by ecosystem grant programs — for example the Stellar Community Fund (SCF) Audit Bank, XRPL Grants, and the Base and Arc ecosystem programs, and the Arbitrum Security Program audit subsidy (`ReceptumEscrow` is live on Arbitrum Sepolia for it). The project does not plan to self-fund them.

The safety rule does not change: [`SECURITY.md`](../SECURITY.md) states that mainnet escrow support will not ship before an independent audit is published. **Escrow contracts that hold customer funds (`ReceptumEscrow` on EVM and Soroban, `receptum_escrow` on Solana) go to mainnet only after that audit.** All three deploy scripts enforce this: they refuse to run without `--audit-report <https://…>`. Rails that hold **no funds** (receipt signing, x402 `exact` receipts, anchors, the verifiers) carry far less risk and can go first, still behind the opt-in.

## 2. Code changes (all behind explicit opt-in, never defaults) — implemented

**The opt-in.** Every path that would sign or send on a mainnet — or on a network Receptum doesn't know — throws `MainnetNotAllowedError` before anything is signed, unless the caller passes `allowMainnet: true` or the process sets `RECEPTUM_ALLOW_MAINNET=1` (exactly `1`). An explicit `allowMainnet: false` refuses even when the environment opts in. Known testnets never need it. Verification is read-only and needs no opt-in. The shared classification lives in `@receptum/core` (`networkClass`, `assertNetworkAllowed`, `MAINNET_NETWORKS`, `TESTNET_NETWORKS`).

1. **`adapter-evm`** — implemented.
   - `MAINNETS` (merged into `NETWORKS`): Base `eip155:8453` (USDC `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`, public RPC `https://mainnet.base.org`, `https://basescan.org`) Arc `eip155:5042` (USDC ERC-20 interface `0x3600000000000000000000000000000000000000`, 6 decimals; USDC is Arc's native gas token; public RPC `https://rpc.mainnet.arc.io`, `https://explorer.arc.io`) and Arbitrum One `eip155:42161` (native USDC `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` from Circle's USDC contract addresses — not the bridged USDC.e; public RPC `https://arb1.arbitrum.io/rpc`, `https://arbiscan.io`). Arc mainnet is live: chain id, RPC and explorer from [docs.arc.io/arc/references/connect-to-arc](https://docs.arc.io/arc/references/connect-to-arc); the USDC address from [Circle's USDC contract addresses](https://developers.circle.com/stablecoins/usdc-contract-addresses) and [docs.arc.io/arc/references/contract-addresses](https://docs.arc.io/arc/references/contract-addresses).
   - Gate: `clientsFor(id, account, { allowMainnet: true })` (or the env var); `deployEscrow`, every `EvmEscrowRail` write and `EvmAnchor.anchor` re-check it (`assertSigningAllowed`), also for hand-built `EvmClients` on unknown chains.
   - `scripts/deploy-mainnet.mjs <eip155:8453|eip155:5042|eip155:42161> --audit-report <url>`: refuses unless `RECEPTUM_ALLOW_MAINNET=1`; takes the key only from `RECEPTUM_MAINNET_DEPLOYER_KEY` and never reads wallet files (no testnet wallet is ever touched); checks the RPC's chain id; prints the plan (network, chain id, RPC, deployer, balance, estimated gas and cost, runtime code hash, audit report); refuses an unfunded deployer; requires typing `deploy ReceptumEscrow to <network>` on an interactive terminal; `--dry-run` stops after the plan. The bytecode is compiled into the package (no artifact file or path argument); after deploying, the contract's runtime code must hash to the planned `runtimeCodeHash` before the record is written.
2. **`adapter-xrpl`** — implemented. `assertNetwork(client, expected = "xrpl:1", { allowMainnet })` replaces `assertTestnet()` (kept as a deprecated alias with the old semantics). Mainnet `xrpl:0` requires the opt-in, checked before the server is even asked; the server must then report exactly NetworkID 0 (a server reporting none is refused). Testnet semantics are unchanged (NetworkID 1). `XrplEscrowRail` and `XrplAnchor` take `network` + `allowMainnet`. Endpoints: `XRPL_ENDPOINTS["xrpl:0"]` = `wss://xrplcluster.com`, `wss://s1.ripple.com`, `wss://s2.ripple.com`.
3. **`adapter-stellar`** — implemented. `STELLAR_PUBNET` (passphrase `Networks.PUBLIC`, Horizon `https://horizon.stellar.org`, Soroban RPC `https://mainnet.sorobanrpc.com` — SDF runs no public mainnet RPC, so production should pass its own `rpcUrl`; the RPC's passphrase is checked before every call). `network: "pubnet"` + `allowMainnet` on `HorizonClient`, `StellarClaimableEscrowRail`, `StellarAnchor`, `SorobanRpcClient` and `SorobanEscrowRail`; signing refuses without the opt-in. Mainnet USDC: Circle's issuer `GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN` (`PUBNET_USDC`), SAC `PUBNET_USDC_SAC` = `CCW67TSZV3SSS2HXMBQ5JFGCKJNXKZM7UQUWUZPUTHXSTZLEO7SJMI75`. Escrow ids carry the network (`stellar:pubnet:<C…>:<id>`). `scripts/deploy-soroban-mainnet.mjs --audit-report <url>` follows the same refusal rules (key only from `RECEPTUM_MAINNET_DEPLOYER_SECRET`, wasm must match `RECEPTUM_SOROBAN_WASM_HASH`, simulated fees in the plan, `--max-fee-xlm` cap, interactive phrase `deploy ReceptumEscrow to stellar:pubnet`). The wasm is read once from the package's fixed path (no path argument); exactly those validated bytes are uploaded, and the wasm hash the upload returns must equal the validated hash before the contract is created — otherwise no contract is created.
4. **`adapter-solana`** — implemented. `scripts/deploy-mainnet.mjs --audit-report <url>` follows the same refusal rules: refuses unless `RECEPTUM_ALLOW_MAINNET=1`; the deployer keypair comes only from the absolute path in `RECEPTUM_MAINNET_DEPLOYER_KEYPAIR`, which only the Agave CLI reads (paths under `$RECEPTUM_WALLETS_DIR`, `~/.config/receptum` or `~/.config/solana`, or named devnet/testnet, are refused, also through symlinks); the RPC's genesis hash — over JSON-RPC and as the CLI sees it — must be mainnet-beta's (`5eykt4UsFv8P8NJdTREpY1vzqKqZKvdpKuc147dw2N9d`); the `.so` (default `program/receptum_escrow.so`, or `--so <absolute path>` for the downloaded CI artifact) is canonicalized with `realpath` (symlinks and `..` resolved) and refused **before it is read** if the path is relative, lies under one of the wallet directories above (also compared with their real paths) or is not a regular file; it is read once and must hash to `RECEPTUM_SOLANA_PROGRAM_HASH`, which must equal `program/deployment.devnet.json` `executableHash`; the plan shows network, RPC, CLI version, deployer, balance, program size, estimated rent (ProgramData + Program, plus the temporary buffer) and fees, and the hash, and an underfunded deployer is refused; interactive phrase `deploy receptum_escrow to solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`; `--dry-run` stops after the plan. After confirmation, only a private snapshot of the validated bytes (mode 600, in the script's private temporary directory) is passed to `solana program write-buffer` — the `--so` file is never read again, so swapping it while the prompt waits has no effect — and before `deploy --final` the uploaded Buffer account must be loader-owned, have the deployer as authority and hash (trailing zeros stripped) to the canonical hash; otherwise nothing is deployed and the temporary keys are kept to resume or close the buffer. It deploys with `--final` (program and buffer keypairs generated in a private temporary directory, never by the CLI), then requires the on-chain ProgramData hash to equal the canonical hash with no upgrade authority before writing `deployment.mainnet.json`. Raw CLI output is never printed (it can contain a seed phrase); failures report only the exit status and a fixed reason.
5. **`verify` and the Python verifier** — implemented. Mainnet RPC endpoints (Base, Arc, Arbitrum One, XRPL `xrpl:0`, Stellar pubnet). `TRUSTED_ESCROWS` has entries for `eip155:8453`, `eip155:5042`, `eip155:42161` and `stellar:pubnet` that are **empty** until a deployment is published, so mainnet escrow receipts report `untrusted deployment` (pending in `@receptum/verify`, unavailable in the Python verifier, which doesn't read escrow state). x402 `exact` mainnet settlement checks work out of the box. Reports carry `network` and `networkClass`; both CLIs print a distinct first line: `=== MAINNET receipt (<network>) — real funds ===` or `=== TESTNET receipt (<network>) — test tokens, no real value ===`.
6. **`server` / `client`** — implemented. `facilitatorUrlFor(network, { facilitators, allowMainnet })` returns the public `https://x402.org/facilitator` for testnets only; mainnets have no default facilitator and need both an explicit URL and the opt-in. `handlePaidJob` refuses mainnet `accepts` without `allowMainnet` (before quoting or charging). `createReceptumFetch({ networks: ["eip155:8453"], allowMainnet: true })` requires `networks` (a missing or empty list throws at construction), refuses a mainnet in `networks` or `expected.network` at construction without the opt-in, and rejects receipts on unregistered networks. `@receptum/mcp` runs after settlement and needs no gate: the x402 resource server you configure with `facilitatorUrlFor` is the gate.
7. **Website** — deferred: the site is not in this repository. Reports expose `networkClass` and `networkLabel()` so it can label mainnet receipts distinctly with the same wording as the CLIs.

Tests cover every gate with mocked clients and servers (no mainnet sends): refusal without the opt-in, success with it, testnet unaffected, unknown networks fail closed, and all three deploy scripts' refusal paths. The only network access is a read-only `eth_chainId` against the Base and Arc mainnet RPCs, in the Python suite's `online` tests (skipped with `RECEPTUM_OFFLINE=1`).

## 3. Going live (after the audit, with grant funding)

```sh
pnpm install --frozen-lockfile && pnpm build
# EVM (per chain). Dry run first; nothing is signed.
RECEPTUM_ALLOW_MAINNET=1 RECEPTUM_MAINNET_DEPLOYER_KEY=0x… \
  node packages/adapter-evm/scripts/deploy-mainnet.mjs eip155:8453 --audit-report https://… --dry-run
# Soroban
RECEPTUM_ALLOW_MAINNET=1 RECEPTUM_MAINNET_DEPLOYER_SECRET=S… \
  node packages/adapter-stellar/scripts/deploy-soroban-mainnet.mjs --audit-report https://… --dry-run
# Solana: download the CI artifact receptum_escrow-ci-build of the audited commit first.
RECEPTUM_ALLOW_MAINNET=1 RECEPTUM_MAINNET_DEPLOYER_KEYPAIR=/abs/path/fresh-mainnet-deployer.json \
  node packages/adapter-solana/scripts/deploy-mainnet.mjs --audit-report https://… \
  --so /abs/path/receptum_escrow-ci-build/receptum_escrow.so --dry-run
```

**Solana `receptum_escrow`: reproducible build.** The canonical build is **Linux x86_64 with the pinned Agave 4.3.0 `cargo-build-sbf`** (platform-tools v1.57, `cargo-build-sbf -- --locked`). The CI job `solana-program` rebuilds it on every push and fails unless it is byte-identical to the committed `packages/adapter-solana/program/receptum_escrow.so` (hash `b270e984…1467c3`, `RECEPTUM_SOLANA_PROGRAM_HASH`). Builds on macOS arm64 produce different bytes from the same source and toolchain (the devnet deployment `4iUzsYkr…` was one and had to be superseded). A mainnet deploy must use the CI artifact (`receptum_escrow-ci-build`) of the audited commit, never a local macOS build, and its hash must equal the committed canonical one. `packages/adapter-solana/scripts/deploy-mainnet.mjs` enforces this: it refuses any `.so` whose hash differs from `RECEPTUM_SOLANA_PROGRAM_HASH`, deploys with `--final`, and checks the deployed ProgramData hash and the absence of an upgrade authority before writing `deployment.mainnet.json`. It needs the pinned Agave 4.3.0 `solana` CLI on PATH and roughly 1.1 SOL for a ~70 KB program (ProgramData rent plus the temporary buffer, refunded by the deploy); the dry run prints the exact amounts.

Then run without `--dry-run`, confirm the phrase, publish the written `deployment.*.json`, and add the address to `TRUSTED_ESCROWS` in `packages/verify/src/index.ts` and `verifiers/python/src/receptum_verify/networks.py` in a reviewed change.

## 4. Operational requirements

- Seller keys in a hardware wallet or KMS — never in files on a laptop. Separate keys per chain. The deploy scripts read the deployer key from the environment only so that it can come from a secret manager.
- Account bindings (SPEC §4.1) published for every mainnet payout account.
- Monitoring: alerts on escrows approaching deadlines (especially Stellar claimable-balance refund windows) and on anchor failures.
- Caps: per-escrow and total-value-locked limits until an audit is complete, enforced off-chain by the seller service and stated publicly.
- Incident plan: who can pause new escrows (the contracts have no admin key by design; pausing = stop opening new escrows client-side).
- Fresh keys for every mainnet account. Several testnet seeds (XRPL testnet buyer, seller and issuer) were exposed in development tool output on 3 Oct 2026; they hold only testnet funds and must never be reused, and no testnet key is ever promoted to mainnet.
